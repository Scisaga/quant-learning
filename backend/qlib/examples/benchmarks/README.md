# 基准模型表现（Benchmarks Performance）

本页面汇总了一批用于 **alpha 挖掘（alpha seeking）** 的基准方法。每个方法都会尝试在每个交易日为所有股票输出一个分数/预测值（例如预测未来超额收益），并将该分数视为“挖掘到的 alpha”。在回测中，分数更高的股票通常会被赋予更高的持仓权重，因此期望带来更高收益。

alpha 的评估通常分两类：

1. **相关性指标**：alpha 与未来收益的相关性（如 IC / Rank IC）。
2. **组合回测指标**：基于 alpha 构建组合后，评估最终投资表现（如年化收益、信息比率、最大回撤等）。
   - 指标解释可参考：https://qlib.readthedocs.io/en/latest/component/report.html#id4

下表给出了基准模型在 Qlib `Alpha360` 与 `Alpha158` 数据集上的结果（中国 A 股 / CSI300）。每个指标展示的是 **20 个随机种子重复实验** 的均值与标准差。

> 说明：表格反映的是每个模型“整套 workflow（数据集 → 训练 → 预测 → 回测/分析记录）”的整体表现。随着 workflow 与模型实现迭代，结果可能会更新。

## CSI500 结果
CSI500 的结果目前并不完整，欢迎补充更多模型结果（PR）。

将 CSI300 的配置迁移到 CSI500 通常很简单：你可以复制一份配置，并把基准指数/市场从 `csi300` 改成 `csi500`（以及对应的指数代码从 `SH000300` 改为 `SH000905`）。示例命令如下：
```
cd backend/qlib/examples/benchmarks/LightGBM
pip install -r requirements.txt

# 新建一份配置，并将 benchmark 改为 csi500
cp workflow_config_lightgbm_Alpha158.yaml workflow_config_lightgbm_Alpha158_csi500.yaml
sed -i "s/csi300/csi500/g"  workflow_config_lightgbm_Alpha158_csi500.yaml
sed -i "s/SH000300/SH000905/g"  workflow_config_lightgbm_Alpha158_csi500.yaml

# 单次运行
qrun workflow_config_lightgbm_Alpha158_csi500.yaml

# 或者自动重复多次并汇总结果
cd  ../../
python run_all_model.py run 3 lightgbm Alpha158 csi500  # 对含随机性的模型建议跑 20 次
```

# 贡献指南（Contributing）

欢迎贡献新的模型与配置。

如果你想贡献新模型，通常可以按以下步骤：

1. 为你的模型创建一个子目录（参考 `backend/qlib/examples/benchmarks/TCTS` 的目录组织方式）。
2. 子目录中建议包含：
   - `requirements.txt`：该模型额外依赖
   - `README.md`：模型简介与运行方式
   - `workflow_config_<model>_<dataset>.yaml`：可被 `qrun` 读取的 workflow 配置（建议覆盖 `Alpha158` 与 `Alpha360`）
3. 若你希望更深度地集成模型实现，可将其作为模块集成到 Qlib 的 `qlib.contrib.model`（具体以你工程中的 Qlib 代码结构为准）。
4. 更新本页面的 Benchmark 表格：表格中的每个指标建议基于 **20 个随机种子** 的均值±标准差。你也可以使用 `backend/qlib/examples/run_all_model.py` 做批量运行与汇总。

完成后即可提交 PR。

# 常见问题（FAQ）

Q：模型名中的 `*.py` 与 `*_ts.py` 有什么区别？

A：`*_ts.py` 通常面向 `TSDatasetH`（会把表格数据自动构造成时间序列样本）；`*.py` 通常面向 `DatasetH`（更偏表格训练）。如果你的特征列存在时序关系，也可以在表格数据上应用时序模型，但需要你在 dataset/handler 层明确构造时序样本。
